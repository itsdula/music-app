# MIDI Device Research: AKAI Professional MPK Mini MK3

- Agent: research-mpk-mini-mk3
- Date of research / access: 2026-10-29
- Scope: **AKAI Professional MPK Mini MK3 only** (also sold as "MPK mini mk3", "MPK mini MKIII", "MPK mini 3"). This dossier does not cover the MPK Mini Play mk3, MPK Mini Plus, MPK Mini MK2, MPK Mini IV or the original MPK Mini. Where a sibling model's documentation came up, it is flagged as **not applicable** and used only to show where the models differ.

## 1. Summary of verified facts

Facts are listed by strength of evidence. Anything not listed here is in section 9 (open questions).

**Identity and connectivity**

- Official name: "MPK mini mk3" / "MPK mini MKIII", AKAI Professional. Announced **2020-08-04** [S12]. SECONDARY.
- Connector: **USB Type-B**. The unit is **USB bus-powered**, needs no extra power supply, and connects with a standard USB-A to USB-B cable [S1 DOC-EXCERPT; S13 SECONDARY]. No USB-C revision was found in any source. UNVERIFIED that none exists.
- **Class-compliant** USB-MIDI. No driver is needed on Windows or macOS [S1 DOC-EXCERPT]. Linux: the kernel has **no device-specific quirk** for any MPK mini MK3 USB ID, so it is handled by the generic class-compliant `snd-usb-audio` MIDI driver [S26 DOC-PRIMARY, inferred from the absence of a quirk].
- **Sustain pedal input:** yes, one 1/4" (6.35 mm) TS jack [S1 DOC-EXCERPT; S13 SECONDARY]. **No 5-pin DIN or TRS MIDI port** appears in any source, and only USB plus sustain are listed [S1, S13]. The absence of a DIN port is SECONDARY.
- **USB Vendor ID 0x09E8** = "AKAI Professional M.I. Corp." [S25 DOC-PRIMARY]. The public `usb.ids` (2026.06.26) **does not list any MK3 product ID**. COMMUNITY sources report **two product IDs, 0x0049 and 0x1049**, which correspond to two hardware/firmware families inside the official v1.26 updater [S17]. UNVERIFIED-COMMUNITY.
- **USB product / port name prefix "MPK mini 3"**: three independent community projects match on this string over ALSA/RtMidi [S18, S19, S20], and a macOS tool matches "MPK mini 3" in the IORegistry and CoreMIDI [S17]. COMMUNITY (strongly corroborated for Linux and macOS). The exact full port strings for each OS are UNVERIFIED (section 8).

**Controls (counts)** [S1, S6 DOC-EXCERPT unless noted]

- **25** velocity-sensitive mini keys.
- **8** backlit pads, velocity- and pressure-sensitive, in **2 banks (A/B)**, so 16 pad assignments. Bank A lights red, Bank B lights green [S6 DOC-EXCERPT]. All community editors model 16 pad records [S18, S19].
- **8** assignable **360° (endless)** knobs, K1–K8 [S1, S6 DOC-EXCERPT]. Each knob is **Absolute or Relative**, set per knob in the Program Editor [S11 SECONDARY; S18, S19 COMMUNITY].
- **1** 4-way thumbstick (X-Y joystick) at the top left. By default **X = pitch bend, Y = modulation (CC1)** [S10, S11 SECONDARY; S6 DOC-EXCERPT for "left/right bends pitch, up/down applies a mod-wheel effect"]. Each axis can be set to Pitch Bend, Single CC or Dual CC [S1 DOC-EXCERPT; S18, S19 COMMUNITY].
- **OLED display**, the first in the MPK mini series [S39 SECONDARY]. It shows program names (for example "PGM: AbletonLive" [S15 COMMUNITY]) and parameter feedback. Size and resolution are UNVERIFIED.
- **Buttons, from the panel photo [S21]**, as printed: ARPEGGIATOR `ON/OFF`, `TAP TEMPO`, `OCT -`, `OCT +`, `FULL LEVEL`, `NOTE REPEAT`, `BANK A/B`, `CC`, `PROG CHANGE` (these three grouped under the legend `PAD CONTROLS`), and `PROG SELECT`. That makes **10 buttons**. The photo shows **no SHIFT button**.

**Programs and default MIDI**

- **8 stored programs**, selected by holding **PROG SELECT** and pressing pad 1–8 [S1, S6 DOC-EXCERPT]. Community editors also expose a volatile **RAM** slot (program 0) [S17, S18, S19] (UNVERIFIED-COMMUNITY).
- Factory Program 1 is **"PGM: MPC"**, which is aligned with MPC Beats [S3, S9]. Factory Program 2 is **"PGM: AbletonLive"** [S14, S15 COMMUNITY]. Programs 3–8: names UNVERIFIED (reviews mention sets for Logic Pro X and FL Studio [S11/SOS excerpt]).
- **Knobs K1–K8 → CC 70–77** in Program 1 "PGM: MPC" [S9 SECONDARY, a Spectrasonics hardware guide]. K8 = CC77 is independently observed on hardware [S17 COMMUNITY].
- **Pads on MIDI channel 10, keys on channel 1** is the configuration Akai's own support articles tell users to set or check [S4, S5 DOC-EXCERPT], and a forum user describes it as "normal" (excerpt). It is **not** stated explicitly as the factory default of every program. UNVERIFIED per program.
- **Pad notes 36–43 (Bank A) and 44–51 (Bank B), and pad CCs 16–23 (Bank A) and 24–31 (Bank B), on channel 10**: these are assumed by the Zynthian "mode enforcer" driver, which runs against the factory program without rewriting it [S20 COMMUNITY]. A generic FL Studio guide also gives Bank A = 36–43 (SECONDARY). Not found in any Akai document. UNVERIFIED (community-corroborated).
- **CC mode** makes the pads send CC instead of Note On. **PROG CHANGE mode** makes the pads send Program Change instead of Note On [S6 DOC-EXCERPT].
- **FULL LEVEL**: the pads always send velocity 127 [S6 DOC-EXCERPT]. It affects the pads only, not the keys [S24 COMMUNITY excerpt].
- **Arpeggiator**: modes Up, Down, Excl, Incl, Order, Rand. Divisions 1/4, 1/4T, 1/8, 1/8T, 1/16, 1/16T, 1/32, 1/32T. Octave range 1–4. Latch. Swing. These values are printed above the keys [S21 photo] and match community editors [S18, S19].
- **External sync**: arpeggiator and Note Repeat follow external MIDI clock when Clock Source = External is set in the Editor [S1 DOC-EXCERPT]. **TAP TEMPO is disabled** when synced externally [S6 DOC-EXCERPT]. Whether the MK3 **sends** MIDI clock is UNVERIFIED (no evidence found).

**Editing protocol**

- The official **MPK mini mk3 Program Editor** talks to the unit with **MIDI System Exclusive over the normal USB-MIDI port**. Several working open-source editors do the same over ALSA/RtMidi [S18, S19, S20, S17; S23 excerpt]. COMMUNITY.
- **Akai does not publish a SysEx specification for the MK3.** None was found, and a 2022 write-up notes the unit shipped without even a MIDI implementation chart [S24 excerpt]. AKAI's SysEx manufacturer ID is **0x47** [S27 DOC-PRIMARY]. The MK3 model byte **0x49** and the command set are **UNVERIFIED-COMMUNITY**.
- **No documented, legally clean protocol exists.** All protocol knowledge is community reverse engineering, and the main implementations are under GPL. See section 5.

**Firmware**

- Known firmware: **v1.18** (file date 2020-06-01) and **v1.26** (file date 2021-04-29) [S16 COMMUNITY archive]. v1.26 is the current official updater as of 2026-09-29 [S17 COMMUNITY]. Akai's support page references an updater named `MPKmini3_Updater_v1.18` [S2/S16 excerpt].
- Firmware-update mode: hold **BANK (A/B) + PROG SELECT** while connecting USB [S2 DOC-EXCERPT; S17 COMMUNITY].

**Physical**

- **12.5" W × 7.13" D × 1.75" H, 1.65 lb** [S1 DOC-EXCERPT]. That equals 318 × 181 × 44 mm and about 750 g; a review gives the same figures [SECONDARY].

**Browser / host**

- Web MIDI ships in Chrome/Edge 43+ and Firefox desktop 108+ (gated behind a site-permission add-on). It is **not supported in Safari or any WebKit browser, including iOS** [S28 DOC-PRIMARY]. A secure context is required [S28, S29]. **Chrome prompts for all MIDI access, not just SysEx**, since Chrome 124 (rolled out to all users by 125) [S30 excerpt of official Chrome blog].
- Electron: permission strings `midi` and `midiSysex`. **Electron approves all permission requests by default** unless the app installs a handler [S31 DOC-PRIMARY].
- Tauri: the `Midi` webview permission is mapped only on Windows (WebView2) and Android. macOS, Linux and iOS backends are "Not yet supported" [S32 DOC-PRIMARY, dev branch]. Native alternative: Rust `midir` 0.11.1 (MIT) [S34].

## 5. Program-editing protocol: findings and legal status

**Transport.** The official Program Editor (Windows/macOS, version around v1.0.x per an Akai compatibility page excerpt; exact version UNVERIFIED) exchanges **standard MIDI SysEx over the class-compliant USB-MIDI port**. This is shown in practice: the editor's traffic was captured through ALSA while it ran under WINE [S23 excerpt], and four independent open-source tools read and write programs with ordinary ALSA/RtMidi/mido SysEx [S17, S18, S19, S20]. Nothing proprietary sits at the USB level for editing. Firmware updating is a separate path through a dedicated updater and a bootloader mode [S2, S17].

**Official spec.** **No Akai-published SysEx or MIDI implementation document for the MK3 was found** after targeted searches. A 2022 note states the unit has no MIDI implementation chart and the editor's SysEx is undocumented [S24 excerpt]. Akai has published SysEx specs for some older or professional products (e.g. Z4/Z8/MPC4000), but not for this one.

**Manufacturer ID.** `0x47` = Akai Electric Co., Ltd. [S27] (DOC-PRIMARY via the Wireshark registry copy; the midi.org table itself was not reachable).

**What the community projects claim** (all **UNVERIFIED-COMMUNITY**; listed for orientation, not as a spec):

Minor inconsistencies between community sources: keybed-octave raw maximum is 7 in mpk3-settings but 8 in Zynthian, and sysex-controls shows −4…+4. Offsets are counted from different origins (with or without F0, with or without program byte). These do not affect the high-level picture but show the layouts are not authoritative.

**Legal / licensing assessment** (not legal advice):

1. **No documented, legally clean protocol exists.** There is no Akai spec or licence grant.
2. The **GPL-licensed implementations cannot be copied** into a non-GPL Studio codebase. Code, tables and comments copied from them would bring GPL obligations with them. MPKill8 has **no licence**, so it cannot be reused at all.
3. Interoperability facts (which bytes mean what) are generally not copyrightable, and a **clean-room re-derivation** by capturing our own traffic with the official editor and our own unit is the defensible route. Akai's software EULA terms were not reviewed (blocked) and should be checked before any capture-based work.
4. Writing programs can overwrite user presets. The firmware will accept out-of-range values [S17]. **Recommendation:** Studio v1 should **not** send SysEx to the MK3. Treat program read/write as a later, opt-in, hardware-tested feature.

## 6. Layout reference (for an original illustration)

**Source and method.** The layout was measured from the top-down product photo inside the annotated diagrams in S21 (`assets/images/SESSION.png` and `DEVICE.png`, 847×548 px; the device occupies about 536×293 px). It is corroborated by S37 (joystick "top left") and the official control list [S1, S6]. **The photo is very likely Akai's copyrighted product image (logo visible). Use it only as a measurement reference. Do not ship it or trace it.** The overlaid arrows and the coloured pad icons in S21 were added by that project's author and are **not** hardware features. Akai's own manual diagram (S6) could not be opened, so **no second image source was available**. Coordinates are approximate to ±0.01, and every value should be re-checked against the official manual diagram when access allows.

**Normalisation.** x, y, w, h are fractions of the **top-panel bounding box including the side cheeks**. Origin is top-left, x to the right, y towards the player. The photo's box is about 1.83:1. The official footprint (12.5" × 7.13") is 1.75:1, so the photo includes a little perspective or chassis lip. If the SVG viewBox uses the official 1.75:1 ratio, scale y by about 1.046.

**Prose description (standard black/red colourway).**

- Matte **black/dark-grey top panel**, with **red side cheeks** on the left and right ends (each about 1% of width) in this colourway.
- **Upper half, left to right:**
  1. A narrow **left control column**. At top-left sits the **thumbstick**: a red domed cap in a dark circular surround. Below it, a printed bracket labelled **ARPEGGIATOR** groups **ON/OFF** and **TAP TEMPO**, joined by a short line. Below those, two more rows of the same small rectangular buttons: **OCT −**, **OCT +**, then **FULL LEVEL**, **NOTE REPEAT**. The buttons are dark with red legends.
  2. In the centre-left, a **2×4 pad grid**. The top row is **PAD 5 – PAD 8** and the bottom row is **PAD 1 – PAD 4**. Each "PAD n" legend is printed small, above the pad's top-left corner. The pads are large rounded squares with a lit outline.

## 9. Open questions requiring a physical-device test

Hardware-in-the-loop checklist. Record firmware version, USB PID, OS and host for each run.

**Identity**

1. Read the USB descriptors on macOS, Windows and Linux: VID, PID (0x0049 or 0x1049?), iManufacturer, iProduct, iSerial, and iJack strings. Record which PID the test unit has.
2. Record the exact MIDI input and output port names in: Chrome on each OS, Firefox (add-on flow), Electron, macOS Audio MIDI Setup, Windows (WinMM and Windows MIDI Services if present), Linux `aconnect -l` / `amidi -l`.
3. Confirm the firmware version shown on the OLED at boot, if it is shown.

**Factory defaults (do a factory restore first via S3)** 4. For each of Programs 1–8: program name, keys channel, pads channel, Bank A/B pad notes, pad CCs, pad PC numbers, knob CCs, mode, min and max, joystick modes and CCs, aftertouch mode, arp defaults, clock source, tempo, taps. Shortcut: open the eight factory `.mpkmini3` files in the official Editor. 5. Keybed lowest note at octave 0. Octave range limits. Whether pressing OCT − and OCT + together resets the octave. 6. Sustain pedal: CC number (64?), values (0/127?), channel (keys channel?), and polarity with normally-open and normally-closed pedals. 7. Joystick: X centre value and dead zone. Does Y-down send anything in factory Program 1 (CC1 only on up? both directions?). Behaviour of Y in Dual-CC mode. 8. Knob Absolute: confirm 0–127 range and step size at slow and fast turns. Knob Relative: the exact encoding (e.g. 1/127, 63/65, 1/65) and acceleration. 9. Pads: velocity range. Aftertouch messages when enabled (channel vs poly). Note-off velocity. Behaviour with FULL LEVEL. 10. Pad CC mode: value on press and release (velocity vs 127, 0 on release?). Momentary vs toggle. 11. Pad PC mode: PC numbers sent. Is a Bank Select sent too?

**Arp / Note Repeat / clock** 12. Does the arp output on the keys channel? Does Note Repeat output on the pads channel? 13. With Clock Source = External: does the unit follow Clock, Start, Stop and SPP from Studio? Does the arp stop when clock stops? 14. Does the MK3 ever **transmit** MIDI Clock, Start or Stop (Internal clock, arp running)? 15. Exact swing values available from the keys vs the Editor.

**Output from the device on state changes** 16. What is sent when a program is loaded with PROG SELECT + pad (PC? SysEx? nothing?). 17. What is sent on BANK A/B, CC, PROG CHANGE, ARP, OCT, FULL LEVEL and NOTE REPEAT presses (expected: nothing).

**Input to the device** 18. Do pad LEDs respond to incoming Note On or CC on any channel? Does the OLED react to anything incoming? 19. Does the unit answer a Universal SysEx Identity Request (`F0 7E 7F 06 01 F7`)? This is a standard, documented message, so it is safe to try.

**Velocity curve** 20. Confirm the hidden curve editor (hold FULL LEVEL about 5 s, K1–K4) on the test firmware, and whether the curve is stored per program or globally.

**Hosts** 21. Chrome: confirm the prompt appears for non-SysEx access and the separate SysEx prompt. Confirm `permissions.query` states. 22. Tauri on Windows: does `navigator.requestMIDIAccess()` work in WebView2 by default? Does `{sysex:true}` raise the permission event? 23. Hot-plug: unplug and replug during a session. Check the `statechange` events and whether port IDs persist.
